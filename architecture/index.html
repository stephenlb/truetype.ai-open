Orchestration

src/truetype/service.py

Decide what to render, in what order, and how to score it back.

system_one()

Non-string state is serialized with json.dumps(indent=2). Each spec becomes a typed Question, then prompts are rendered and scored.

build_question() render_batch() score_question()

prefix-cache branch

Cache on: ensure_prefix_capacity(len(questions)), then score one question at a time against its own prefix — sequential cached calls beat one uncached batch. Cache off: a single score_batch() over all prompts.

scoring over full readout

score_question() gets the full 26-letter logit dict, never the truncated top-k, so a question with more options than top_k is not cut off. Renormalization happens over the question's own legal letters.

usage accounting

input_tokens = chars // 4 across rendered prompts; output_tokens = number of questions — one token each, by construction.

warm()

Prefills the prefix of known questions before a timed loop. Does not beat a cold miss; it just moves the prefill outside the caller's clock. A Doom run reuses one prefix ~40 times.

debug payload

include_debug returns the exact prompt text, raw letter logits, and the ranked top-k letters per question.

Prompt & primitives

src/truetype/render.py
src/truetype/questions.py

Turn typed questions into base-completion text with a cacheable head.

block layout

Each example is Choices: … Question: … Text: … Answer: X. The answer-relevant scaffolding sits first, the judged text last, so the head is byte-identical across calls for the same question.

noul examples

A fixed bank of 6 demonstrations with predicates that differ from the target question. They teach the letter slot; the target's own options carry the task, so example labels stay truthful instead of being relabelled.

GENERIC_EXAMPLES DEFAULT_EXAMPLE_COUNT=6

choice / score examples

One synthetic roundtrip per option, generated from the caller's criteria. Options are visited low, high, then ascending so no A,B,C positional shortcut exists.

_interleaved_order()

the Answer: slot

No trailing space after Answer:. The natural continuation is the space-prefixed letter token "▁Y", matching the examples. A trailing space stranded the space and dropped scored-letter mass to 0.0000 (vs 0.9871).

three primitives

noul → Y/N (max 2 options). choice → named criteria map, one letter each, max 26. score → ordered levels, one letter each, max 26.

instruction rewriting

_predicate_forms() turns "Does the text request a refund?" into a Yes sentence and a No sentence used as the option text.

Letter engine

src/truetype/engine.py

Lazy load, one forward, cache the prefix KV.

load() — engine.py:110

Double-checked under a Lock, idempotent. Device auto: cuda → mps → cpu. Dtype auto: float32 on cpu, bfloat16 elsewhere. Left-padding, eval(), low-cpu-memory load.

letter token map — :160

Tries " A" then bare "A". All 26 must be single tokens and distinct, from one variant; mixing shapes makes logits incomparable. No variant → the engine refuses to run.

letters_with_leading_space=true

score_batch() — :210

Splits prompts into chunks of max_batch_size=16, tokenizes with padding, and runs one forward per chunk: logits_to_keep=1, use_cache=False, then logits[:, -1, :].float().

score_with_prefix() — :297

Per suffix: reuse the prefix KV if it is there, otherwise fall back to a full uncached pass. Disabled cache or empty prefix routes straight to score_batch().

ensure_prefix_capacity() — :273

Grows one-way to cover every distinct prefix in the request, clamped to the hard cap. An undersized LRU evicts before a prefix is revisited and every call repeats prefill: 8051ms @ cap 8 vs 1771ms @ cap 10 for 10 questions.

counters

prefix_cache_hits, misses, evictions, exposed via /health. The cache is an OrderedDict; move_to_end on hit, popitem(last=False) to evict.

05

Weights

google/gemma-4-12B

Base checkpoint. The letter after the prompt is the answer.

base, not chat

No chat template and no multi-token preamble, so nothing stands between the prompt and the first predicted token. One forward() yields the whole answer.

footprint

~22GB download cached under ~/.cache/huggingface, ~24GB resident in bf16, plus ~127MB of KV per cached 369-token prefix. The default cap of 64 entries can reach ~8GB of KV.

KV reuse shape

A cached prefix is the prefix slice of one real forward pass, cropped back to prefix length with cache.crop(-tail_len) after each use. Nothing is re-tokenized or replayed for the head.

batch policy

With caching on, the service scores questions sequentially instead of batching: on this hardware the prefill saved per question outweighs batch throughput.

Letter readout

src/truetype/letters.py

Gather the 26 letters, check their mass, softmax the legal ones.

batch_letter_logits() — :118

Indexes the 26 A–Z token ids out of [batch, vocab] into one logit dict per row. This is the model's raw vote, before any renormalization.

batch_letter_mass() — :134

Fraction of the full-vocabulary probability sitting on A–Z, via exp(logsumexp(letters) − logsumexp(vocab)). If it approaches zero, the argmax is noise in the distribution tail.

distribution_from_letter_logits() — :85

Rank, keep top-k (clamped to 1..26), softmax at temperature over just those k, so reported probabilities sum to 1 across surfaced options.

temperature=0.7 top_k=5 LETTERS=A..Z

failure modes

LetterLogitError on non-letter keys, an empty readout, or a non-finite softmax denominator. Low temperature cannot change the argmax — it only sharpens score and confidence.

Return path

200 OK · JSON

Raw letters become typed answers on the way back up.

26 logits → softmax over legal letters → choice argmax + confidence → noul = P(yes) → score = Σ i·pi → answers[qid]

noul

Probability of "yes" over the two legal letters, returned as noul.

choice

Argmax label plus the full probability map and an entropy confidence, 1 − H / log n: 1.0 when all mass sits on one option.

score

Expected level Σ i·pi over the ordered criteria, with the same confidence. Read the score together with confidence.

envelope

{model, answers, usage} — the shape TypeSafe documents, so a client can repoint its base URL without touching its parsing.

Prefix KV cache

engine.py:341 · hit vs miss

Lookup keyed by the prefix string

The full prompt is always tokenized as one string and the cached ids are compared against its head, so the tokens fed to the model are exactly the tokens the uncached path would use.

MISS — cold

  1. Tokenize prefix + suffix in one pass with special tokens.
  2. Run one full forward with use_cache=True, read logits at the last position.
  3. If the prompt head equals the tokenized prefix, crop the tail off the KV and store (cache, prefix_ids).
  4. Evict the oldest entry while the LRU exceeds max_cached_prefixes.

HIT — warm

  1. Prefix found and this prompt truly starts with its ids (and is longer).
  2. move_to_end marks it most-recently-used.
  3. Prefill only the tail: past_key_values=cache, cache_position=arange(prefix_len, total).
  4. Read logits, then cache.crop(-tail_len) so the entry is prefix-only again.

boundary safety

A tokenizer merge across the prefix/suffix boundary makes the head check fail and the prompt silently falls back to a full pass. Correctness never depends on the cache.

single writer

All cache work runs under _cache_lock; model loading runs under a separate _lock. The engine is safe to share across threads.

why capacity is auto-grown

The LRU must cover every distinct question in a request, or it evicts a prefix before that prefix is ever revisited and the speedup disappears.
